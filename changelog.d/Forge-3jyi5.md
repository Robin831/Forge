category: Added
- **Per-anvil changelog fragment convention** - The stranded-branch completion probe now reads the accepted fragment shapes from the anvil's own config (`anvils.<name>.changelog.dir` and `fragment_globs`, with `{bead}` standing in for the bead id) instead of Forge holding a second, independent copy of each repository's convention beside the repository's own CI gate. The default is unchanged, so an anvil that configures nothing behaves exactly as before; a repository whose gate accepts a shape the built-in grammar does not now says so in config rather than needing a change in Forge. Both fields hot-reload. (Forge-3jyi5)
- **Changelog fragment drift is reported instead of read as unfinished work** - When no fragment matches, Forge now names the files under the fragment directory that plainly belong to the bead but that the rule rejected — in the daemon log and in the needs_human escalation itself, alongside the setting that resolves the disagreement. Previously the disagreement was a silent false negative whose only symptom was an escalation an operator had to read and disbelieve. A `bd` child bead's `<parent>.<n>.md` is deliberately not reported, since refusing it is correct. The `create-pr` refusal now quotes the rule in force rather than a hardcoded sentence describing it. (Forge-3jyi5)
