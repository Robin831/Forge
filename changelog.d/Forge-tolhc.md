- **Temper `tolerate_host_crash` for flaky .NET test-host teardown crashes** - A per-step opt-in flag that re-classifies a non-zero exit as a pass when the output shows a completed all-passed .NET test summary AND an explicit test-host crash/abort marker (e.g. `Test host process crashed : Out of memory`). This is for repos whose `dotnet test` host occasionally OOMs/crashes at teardown after every test has already passed — VSTest then returns non-zero with zero failing tests, which previously failed the api-test step and burned Warden fix iterations on green PRs (observed repeatedly on Munin). Conservative: a real test failure (`Failed: N>0`) or a build error (no crash marker) still fails the step; enable per step via `temper.steps[].tolerate_host_crash: true`. The underlying test-suite memory usage is tracked separately. (Forge-tolhc)
