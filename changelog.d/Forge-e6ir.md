category: Fixed
- **A worker whose process is gone is failed, not stalled** - The stale detector now checks that the process a silent worker row records is still running before it leaves the `stalled` mask in place. `stalled` is recoverable and is only ever cleared by fresh log writes from the very session that has died, so a crashed or externally killed worker held its `max_total_smiths` slot forever — on a single-slot forge that stopped dispatch entirely with nothing in the log but the same "limit reached" line every poll. Such a row is now marked `failed` (emitting `worker_process_gone`) and its slot released. The decision needs the same gone pid on two consecutive detector passes, because a healthy pipeline passes through a window that looks identical — the phase flips to `smith` before the new spawn records its pid, over a log a long temper/warden run has already left stale — and `failed` is terminal, so acting on one sighting would end a live worker's row and hand its slot to a second dispatch for the same bead. The first pass therefore applies the ordinary recoverable mask and a later one escalates it (`state.SilentStalledWorkers`, which is also the only thing that re-examines a row stalled by an earlier daemon lifetime); a pid that has changed, a process that reads alive, or resumed log activity starts the count again. The check is confined to the `smith` and `schematic` phases, whose pid names the session they are in, since a row in `temper` or `warden` carries the pid of the Smith that finished before it by design; rows handed off live to Bellows (`monitoring`), operator-paused rows, and rows recording no pid keep the previous behaviour throughout. (Forge-e6ir)
- **The global Smith limit says when one worker has been holding it** - `global smith limit reached, skipping dispatch` reads identically whether a busy forge is turning its slots over every cycle or one wedged worker has held the same slot since Tuesday. The daemon now tracks *which* workers occupy the limit across polls and adds a WARN naming the blocking worker, its bead, phase and age once the same one has held it for more than `settings.wedged_limit_polls` consecutive polls (default 3; negative disables). Ordinary saturation keeps its unchanged INFO line, and a wedged holder is announced once per run rather than every poll interval. (Forge-e6ir)
