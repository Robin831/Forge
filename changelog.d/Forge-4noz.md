- **Kiln preview service restart policy** - A preview service can opt into being relaunched when its process dies after becoming healthy, with `restart: on-failure` and `max_restarts` (default 3, capped at 10) in `.forge/preview.yaml`. The relaunch reuses the same allocated port, re-runs the readiness check and re-derives the preview status, so a recovered service returns to `running` by the same path a fresh start uses. The default stays `off` — a service that dies for a real reason must not be hidden behind a restart loop — and nothing is silent: the exit event says whether a restart is coming or the budget is spent, each attempt emits a `preview_service_restarted` event, and the restart count shows up on the service in the preview panel, the previews payload and `forge preview list`. (Forge-4noz)
