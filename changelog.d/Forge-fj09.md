category: Fixed
- **Stranded-branch recovery recognises `-technical` changelog fragments** - The completion-signal matcher accepted only `changelog.d/<bead>.md` and the dot-delimited `<bead>.<lang>.md`, so a branch carrying only Munin's `<bead>-technical.en.md` / `.nb.md` pair — the normal shape for a technical-only change — read as incomplete, and completed, pushed work was escalated to needs_human instead of having its PR opened. The bead id may now be followed by a `.` or `-` delimiter and an alphabetic kind or language. (Forge-fj09)
- **A child bead's changelog fragment is no longer the parent's completion signal** - bd's hierarchical ids are `<parent>.<n>`, so a child's `changelog.d/<parent>.7.md` is the parent id followed by a delimiter. Since the probe reads the branch tip's whole tree, a child fragment merged to main weeks earlier would have read as the parent's own completion signal and opened a PR for work that never happened. Requiring the segment after the delimiter to be alphabetic accepts `.en`/`.nb`/`-technical` and excludes a child's ordinal. (Forge-fj09)
- **`forge changelog validate` and the daemon's probe share one matcher** - `changelog.ValidateFragmentExists` accepted only `<bead>.md` and `<bead>.en.md`, so a bead whose fragment set was `<bead>-technical.en.md` read as complete to stranded-branch recovery and missing to the CLI. Both now call `changelog.FragmentMatchesBead`, which is the single definition of the accepted names. (Forge-fj09)
