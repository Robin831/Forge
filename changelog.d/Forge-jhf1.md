category: Fixed
- **Decomposition children get GitHub issues** - The Schematic now runs an explicit `bd github push` for every sub-bead a decomposition creates and verifies each got an `external_ref`, and the PR step pushes-and-refetches a bead that still has none before opening its PR — bd's per-command auto-sync only covers the last-touched bead, so children were created issueless, their PRs closed nothing on merge, and the bead claims went stale. (Forge-jhf1)
- **PR issue references derived from the worked bead only** - PR bodies now always carry a reference derived from the bead's own `external_ref`, in the cross-repo-safe `owner/repo#N` form for full issue URLs (a bare `#N` from a PR in another repository silently closes nothing). Stray model- or description-authored `Closes`/`Fixes`/`Resolves` lines are demoted to `Refs` instead of suppressing the correct injection or closing a sibling bead's issue, and the Smith prompt no longer asks the model to write closing references at all. (Forge-jhf1)
- **No-close (innmeldt) and wicket source issues referenced with Refs** - An `external_ref` issue carrying a label from the new `settings.github_no_close_labels` set (default `innmeldt`) is referenced with `Refs`, never `Closes`, so user reports stay open until the reporter verifies; the issue named by a wicket `Source:` line in the bead description always gets its own `Refs` line. (Forge-jhf1)
