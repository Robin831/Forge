category: Changed
- **Bead writes can go through Varde** - with `FORGE_VARDE_URL` and `FORGE_VARDE_KEY_FILE` set, every bd write the Forge makes (claims, releases, notes, labels, closes, dependencies, new beads) runs as the hidden `forge bd-varde` command, which sends it to Varde's bead tools with the Forge's own key and answers as bd would; reads stay on bd, so the Forge's database user can be read-only. Each anvil names the epic its own new beads go under with `beads_parent`. A bead the Forge escalates now keeps its dispatch label and gets `needs-human`, which the poller skips and a retry takes off; parts of a split bead get the parent's dispatch label when they are created. Through Varde, adding a dispatch label by hand (Hearth's tag, wicket auto-dispatch, the ledger) is refused: a hand-over goes through Varde's `beads_forge_label`. `bd github push` is dropped. (DevInfra-gbx.8)
