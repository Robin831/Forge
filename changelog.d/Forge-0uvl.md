category: Changed
- **Depcheck blocked-scan escalations say what to do** - A blocked dependency scan no longer reports git's raw stderr as its headline. The Needs Attention entry now names the anvil and its checkout, enumerates the blocking paths from `git status` — annotating the pod-local `.beads/config.yaml` and bd-regenerated `.beads/.gitignore` so an operator recognises them as expected rather than as the problem — and gives the single recoverable command that resolves the condition — bounded honestly, so where more paths are blocking than fit one readable command the line says it sets the first five aside and points at `git status` for the rest, rather than reading as the whole fix. git's own output is kept as the trailing `git output:` evidence. Which condition is escalated, and when it is suppressed, is unchanged. The blocking paths are read from `git status --porcelain -z`, so a filename containing ` -> ` or a space is reported and stashed as itself rather than cut into a path that is not in the tree; a scan whose paths could not be enumerated says so instead of claiming nothing unexpected is modified; the `not a git repository` remedy pairs `forge anvil remove` with the add, which alone would be refused as a duplicate; and the whole entry is budgeted against the same `maxFailureDetailBytes` bound the git evidence inside it already respected.
