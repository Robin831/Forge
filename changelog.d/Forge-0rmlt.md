category: Changed
- **Warden staleness sweep now needs age AND inactivity, and protects supersession termini** - A learned review rule is archived only when it has BOTH aged past `warden.archive_after_days` and gone unused past the new `warden.inactive_after_days` (unset falls back to the age threshold, so existing deployments are unchanged; there is deliberately no value that switches the inactivity half off, since that is the defect rather than a mode). `IsStale` returns the reason that decided each rule — too young, recently used, protected, or aged and inactive — instead of a bare bool. On top of that, a rule other archived rules were merged into is no longer swept by default: archiving it would retire the merged content of the whole chain behind it with nothing left on the active file to say what went, so it is kept and named in the flush log, the Smelter commit body, the batch PR body and `forge warden consolidate`. `warden.allow_archive_terminus`, or `forge warden consolidate --force`, archives them anyway.
