category: Changed
- **Warden staleness sweep now needs age AND inactivity, and protects supersession termini** - A learned review rule is archived only when it has BOTH aged past `warden.archive_after_days` and gone unused past the new `warden.inactive_after_days` (unset falls back to the age threshold, so existing deployments are unchanged; there is deliberately no value that switches the inactivity half off, since that is the defect rather than a mode). `IsStale` returns the reason that decided each rule — too young, recently used, protected, or aged and inactive — instead of a bare bool. On top of that, a rule other archived rules were merged into is no longer swept by default: archiving it would retire the merged content of the whole chain behind it with nothing left on the active file to say what went, so it is kept and named in the flush log, the Smelter commit body, the batch PR body and `forge warden consolidate`. `warden.allow_archive_terminus`, or `forge warden consolidate --force`, archives them anyway. (Forge-0rmlt)
- **Terminus guard covers the chain a flush just created** - The supersession index the staleness sweep reads now includes the merges the same run decided on but has not yet written to the archive, so a rule Pass 1 merges out of two old, never-emitted near-duplicates is not archived in the run that created it. Both `warden.inactive_after_days` and `warden.allow_archive_terminus` are hot-reloaded rather than needing a daemon restart, and a rule the guard holds is announced to the daemon log and the activity feed once per anvil instead of on every flush cycle — the line still counts every rule the sweep is holding, naming the newly held ones inside it, so it never reports a smaller sweep than the commit and PR bodies of the same run. (Forge-0rmlt)
