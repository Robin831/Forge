category: Fixed
- **Burnish no longer discards a fix its verification could not confirm** - A review-fix verification timeout used to log a WARN, skip the push, delete the worktree and report the cycle complete, leaving a finished commit reachable from nothing while the next Bellows cycle spent another full Smith run rebuilding it. Verification is now re-run (new `burnish_verify_retries`, default 1) and, if it still does not complete, the commit is pushed marked unverified with a Needs Attention entry — burnish verification is advisory, since every fix lands on a PR that is reviewed again. (Forge-xl50)
- **A review-fix worktree with unpushed commits is never deleted** - Teardown now proves the worktree HEAD is on the remote before removing it. A commit that exists nowhere else keeps its checkout and is surfaced in Needs Attention by SHA and path, so recovery is a push or cherry-pick instead of object-store archaeology. (Forge-xl50)
- **Repeated review fixes against an unchanged PR head are circuit-broken** - Dispatches are counted per PR head (new `max_same_head_review_fixes`, default 2) and escalated to Needs Attention instead of dispatching again; the counter resets as soon as the head moves, so a PR that is genuinely progressing is unaffected. Manual review fixes bypass the breaker, and an unreadable head SHA lets the dispatch through. (Forge-xl50)
