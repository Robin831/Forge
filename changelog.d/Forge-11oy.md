category: Security
- **Proxied Kiln previews are behind the Hearth session** - With `settings.preview_proxy_base` set, a request arriving on a preview hostname now has to come from a signed-in Hearth operator. Where the dashboard host and the proxy base share a registrable parent domain the session cookie is scoped to that parent and simply validated on the subdomain; where they do not, the preview link carries a short-lived signed token that is verified once and exchanged for an HttpOnly, preview-scoped cookie. A request that proves neither is refused — a browser navigation is redirected to the Hearth login, everything else gets a 401 naming what is missing — and Hearth's own cookies are stripped from every request forwarded to a preview, so unreviewed branch code never sees them. (Forge-11oy)
- **`preview_proxy_auth` setting** - New `settings.preview_proxy_auth`: `session` (the default) gates proxied previews as above, `none` is the explicit opt-out for a trusted network. Unrecognised values are rejected at load time and treated as `session` at runtime, so a typo cannot open previews up. (Forge-11oy)
