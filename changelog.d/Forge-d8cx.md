category: Fixed
- **`forge warden consolidate` can now merge clusters** - Pass 1 spawned its AI session in the anvil itself, and Smith's pre-flight refuses any working directory that is inside a git repository without being a linked worktree — so on a real anvil (a main checkout by definition) every cluster failed before a provider was spawned and the pass reported itself as run having merged nothing. Pass 1 now runs in a throwaway detached worktree of the anvil's HEAD, removed on both the success and the failure path; the merged rule still comes back as JSON and is written to the anvil's own rules file. A worktree that cannot be created skips Pass 1 and is reported, rather than falling back to the arrangement that failed. The checkout itself is `internal/worktree`'s `CreateEphemeral`/`Remove`, so it gets that package's stale `core.worktree` self-heal, post-creation `.git` pointer check, timeout tiers and Windows-aware teardown rather than a second copy of them. A worktree that cannot be torn down AFTERWARDS is reported on a second error return of its own — never folded into the run's error, since the callback is free to return a `*warden.WorktreeCleanupError` from a nested call — and never displaces the cluster error the CLI prints: a pass whose merges were kept and persisted must not be reported as one that never ran. Every such teardown now runs on a background context rather than the caller's, so a cancelled daemon shutdown no longer leaves a temp checkout and its git registration behind with nothing to sweep them.
