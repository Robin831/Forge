category: Fixed
- **Hearth no longer reports queued actions as successful before they finish** - Actions the daemon runs in the background (label writes, bead close, stop, PR actions) answered 202 and the UI showed a success toast even when the underlying `bd`/`gh` write later failed, silently discarding the click. The daemon now retains the outcome of every queued request in a bounded store (500 entries / 1h) and exposes it via the new `request_status` IPC command and `GET /api/requests/{request_id}`; the web UI polls that handle and renders a real error toast on failure, or "queued, outcome unknown" when the outcome cannot be determined. (Forge-4r2n)
