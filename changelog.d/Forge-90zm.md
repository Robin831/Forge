category: Fixed
- **Self-deploy restart survives the unit stop** - The restart child was spawned inside forge.service's cgroup with the deploy context attached, so systemd's stop of the unit (and any context deadline) SIGKILLed it mid-restart — Forge read that as a failed restart and rolled back to the stale binary. The restart is now spawned detached: no context at all, `setsid`, and wrapped in `systemd-run --scope --collect` so it runs outside the unit cgroup, falling back to `systemctl restart --no-block` when `systemd-run` is unavailable. The build SHA, binary path, rollback path and exact argv are logged to daemon.log before the spawn so a killed restart stays diagnosable. (Forge-90zm)
