category: Changed
- **Blocked dependency scans escalate once instead of failing nightly** - Depcheck now classifies a git failure as transient (DNS, timeouts, connectivity, credentials) or blocked (detached HEAD with no upstream, a ref the fetch cannot lock, a tree left mid-merge). A transient failure keeps its per-run `depcheck_failed` event and is retried next run; a blocked one is announced once, raises an anvil-level Needs Attention entry naming the checkout and git's own words, and stays silent until the condition changes — then clears itself on the next scan that reads the anvil's manifests. (Forge-4v1w)
- **Depcheck git failure reporting hardened** - A git command killed by its deadline now carries that deadline as a cause, so a timed-out fetch classifies as transient instead of unmodelled; both reporting exits strip and bound git's own words before they reach the log and the activity feed; the Needs Attention headline is rendered by the record rather than written in two packages; and the on-demand scan path gets the same 1-minute timeout floor the scheduled one has, instead of running every ecosystem scan against an expired deadline. (Forge-4v1w)
