category: Added
- **Warden rule usage telemetry** - Learned review rules now record when they were last rendered into a review checklist and how many times (`last_emitted`/`emit_count`, plus a `last_finding` field carried for future finding attribution), stamped by the Warden's own emission path and persisted in the anvil's `.forge/warden-rules.yaml`. `Rule.LastActivityIn` folds the three dates into the most recent evidence a rule is alive, and the staleness sweep (`IsStale`) now reads that rather than the learn date alone — so a rule the selection puts in front of a reviewer every week is no longer retired for the age of its distillation session. All three fields are optional, so existing rules files load and re-save unchanged, an absent value means "never observed" rather than "stale", and an unstamped rule ages exactly as it always did. (Forge-guz02)
- **Atomic writes for the Warden rules and archive files** - `SaveRules` and `Archive.Save` now write via a temp file plus rename instead of truncate-then-write. A YAML sequence cut mid-write is frequently still valid YAML with fewer rules in it, so a torn read was silent — the smelter would copy the short file into the batch PR, or the next flush would persist it, with nothing to distinguish the loss from an archive sweep. The rules file is now written on every review, so the window was entered orders of magnitude more often than before. (Forge-guz02)
- **Emission stamps no longer clobber a concurrent rules-file write** - The stamp re-reads the anvil's rules file immediately before saving and applies itself only where a position still holds the rule that was selected, so a rule learned or a consolidation landed during the review is no longer overwritten by the review's stale copy. A lost stamp stays possible and remains an undercount the consumers read as unknown; a lost rule does not. (Forge-guz02)
