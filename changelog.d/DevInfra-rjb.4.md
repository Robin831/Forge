category: Changed
- **An anvil's checkout and shared Node install follow main** - before each worktree the Forge fast-forwards the anvil's own checkout when it is clean and only behind origin (a dirty or diverged one is logged and left), and runs npm ci in the anvil's own project folder when its shared node_modules no longer matches its lockfile, so worktrees share it again after a dependency bump instead of each installing its own. It refreshes only when no worktree or preview links to that install, never waits for another sync (an OS file lock in git's own directory, freed when its holder exits; a worktree or preview made meanwhile does not link the tree being rebuilt; npm and its children run as one process group, stopped together), and after a failed install waits 30 minutes before trying the same lockfile again (until the Forge restarts). The first worktree after a lockfile change on main can therefore wait for that npm ci: up to 10 minutes a project folder, 25 minutes in all. An install with no record of what it holds (node_modules/.package-lock.json missing, as after an interrupted install) now counts as stale, so it is repaired, not shared. (DevInfra-rjb.4)
