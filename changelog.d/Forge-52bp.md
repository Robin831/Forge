category: Fixed
- **Dispatch always finalises its worker row** - A dispatch goroutine that exited by a path with no status update of its own — the pipeline's abort when a Temper step is killed by a cancelled context, or a panic unwinding the stack — left its worker row claiming a running Smith, so the row counted against `max_total_smiths` forever and kept a live panel open for a process that was gone. A deferred backstop now marks such a row failed at every exit and records a `worker_abandoned` event naming the status it replaced. It is idempotent with the roughly thirty existing termination sites (the decision is made in the UPDATE's own WHERE clause) and never touches a row that was handed off live on purpose: `monitoring`/`detached`, which Bellows owns after a successful dispatch, `paused`, which a cold resume owns, or one the watchdog has masked as `stalled` over any of those — the push and PR creation that follow warden approval write no log, so a row Bellows already owns can be stalled, and failing it would assert an ending over a live handoff and destroy the watchdog's own recovery. A row stalled over a dispatch status is still failed: nothing will move it again, and it holds a dispatch slot for as long as it stands. (Forge-52bp)
- **Crucible finalises its parent's worker row** - A Crucible run finalises its parent's claim row once, unconditionally, before the block branches on the outcome — `done` when the epic completed, `failed` otherwise — so a successful epic is no longer recorded as a failure, a run that reports neither an error nor success no longer falls through to the backstop, and `worker_abandoned` keeps naming only the exits nothing finalises. (Forge-52bp)
