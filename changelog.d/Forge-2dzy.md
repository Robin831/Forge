- **Per-child `independent` label** - A child of a parent that opted into epic orchestration (`crucible`/`epic-branch:<name>`) can now carve itself back out with an `independent` label: the Crucible never claims it or its subtree, it is not stamped with the epic branch (worktree from main, PR to main) and it is not withheld from the ordinary dispatch loop, so tagging it `forgeReady` runs it standalone alongside the epic. It is excluded from the epic's completeness set entirely — its work could never land on the feature branch, so an open independent child no longer holds up the epic's final PR — and the queued-children event names the beads it excluded. The label is inert on beads that are not children of an orchestrated parent, and wins over an opt-in label on the same bead. The label is read off each bead's own record (`bd show --json` reports dependents as edge summaries without labels, so a child's opt-out is resolved by a second lookup); a child whose labels cannot be read is treated as an ordinary child at every gate. Adding `independent` to a parent that is *already* orchestrating orphans its feature branch — see the warning in `docs/configuration.md`; the daemon WARNs once per bead carrying both an opt-in and the opt-out. (Forge-2dzy)
