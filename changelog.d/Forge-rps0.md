category: Changed
- **Assay retries turn-budget failures once** - An Assay deep pass that ends on `error_max_turns` is now re-run once in a fresh session with identical inputs before it counts as a failed pass, so a run no longer loses that pass's coverage when the model spends its budget exploring instead of answering. The retry is bounded and never recurses; a pass that fails twice is still reported exactly once, as `logic — error_max_turns`, in both the worker status text and the PR summary comment. (Forge-rps0)
- **Assay pass cost counts every session it paid for** - A failed Assay session's cost now rides on the pass error instead of being dropped, so a retried pass reports the exhausted session plus the retry rather than the retry alone. An `error_max_turns` session burns the whole turn budget, making it the most expensive kind, so the run total that feeds bead and daily cost tracking no longer undercounts by roughly a full session on exactly the runs the retry exists to handle. (Forge-rps0)
- **A failed Assay run records what it spent** - A run that returns no result — triage failed, or every deep pass did — now carries its billed cost out on the error (`assay.RunCost`), and the daemon records it on the run exactly as it does for a successful review. Previously those runs recorded zero, so the most expensive failures were invisible to the assay spend that `daily_cost_limit` is measured against. (Forge-rps0)
- **Per-pass turn telemetry in the Assay log line** - Each pass now records the turns its session used, how it terminated, and whether it was retried; the daemon emits them as a `passes` field (`pass=logic turns=12 term=error_max_turns retry=1`) so the turn budget can be tuned against real runs. (Forge-rps0)
