category: Fixed
- **Stalled workers stay visible on the web dashboard** - A worker the watchdog marks stalled keeps its live panel (and its open log stream) instead of vanishing mid-run, and now carries its own orange `stalled` chip. It also counts against the Smith cap again, so the Workers pane and the panel grid stop offering one idle slot more than the daemon will dispatch into. The slot-status set and chip colours moved to `src/lib/workerStatus.ts` so the three surfaces that read them cannot drift apart again. (Forge-wl5s)
- **Idle Smith slots on the dashboard match the daemon's own count** - The dashboard reproduced only the status half of `state.ActiveDispatchWorkers`, so a running quench/burnish/rebase/assay worker — which has a real id and log path, and whose phase the daemon excludes from dispatch capacity — ate a Smith slot the daemon would happily dispatch into. Both surfaces now count on both axes; such a worker still gets its row and its live panel. (Forge-wl5s)
- **A Go test now guards the dashboard's copy of the dispatch vocabulary** - `TestFrontendDispatchStatusesMatchDispatchQuery` and `TestFrontendBackgroundPhasesMatchPayloadPhases` read `lib/workerStatus.ts` and compare it against the SQL the capacity queries are built from, so the Go list moving fails a test instead of silently mis-reporting capacity. The status axis is compared with no carve-out, and the phase axis against the vocabulary the workers payload can actually carry — the SQL list plus the display rewrites the IPC handler applies (`state.PhaseDisplayRewrite`). (Forge-wl5s)
- **A ready-to-merge bellows monitor no longer eats a Smith slot on the dashboard** - The workers IPC handler rewrites a ready monitor's stored `bellows` phase to `ready_to_merge` before the payload leaves the daemon, and that value was in no background-phase list on the UI side; its exclusion rested entirely on the row's status. It is now excluded on the phase axis in its own right, and the capacity predicate mirrors the daemon's status list exactly (`monitoring` included) rather than borrowing the panelling set. (Forge-wl5s)
- **A killed worker gets a red chip** - `killed` is terminal and a routine `kill_worker` / `forge queue stop` outcome, but none of the chip maps folded into `lib/workerStatus.ts` ever styled it, so it rendered as an unrecognised status everywhere. It now draws in red like `failed`, and a test pins every terminal status against the map. (Forge-wl5s)
- **One home for worker-status vocabulary** - The terminal, steer and pause/resume status sets moved out of `api.ts` (the transport layer) into `lib/workerStatus.ts` beside the slot set, and `HistoryPage` now draws its status chip from the shared map — it held a fourth copy in which `done` had drifted to a different colour from the live surfaces. (Forge-wl5s)
