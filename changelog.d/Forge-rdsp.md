category: Fixed
- **PRs no longer strand in needs_fix when a fix never re-dispatches** - Two reinforcing gaps left a PR parked in `needs_fix` with green CI but unresolved review threads (or failing CI / conflicts) and no worker ever re-dispatched, so it never reached ready-to-merge and never surfaced in Needs Attention (observed: PR #4257 / Fhi.Metadata-hyc4g). (1) Parked lifecycle actions used a single latest-wins slot per bead, so a CI-fix queued while a bead was in flight silently overwrote an already-parked review-fix — the fix that would have cleared the threads never ran. Parked actions are now keyed per action type (latest-wins only within a type) and drained in priority order (CI → review → rebase). (2) The "still failing/unresolved" retry branches in Bellows re-dispatched only when `pr.Status != needs_fix`, a proxy that wedged any PR sitting in `needs_fix` with no active worker. They now key off whether a fix worker is actually in flight for the bead (the same `activeBeads` lock the dispatcher uses), so a stuck PR re-dispatches until its threads resolve or the attempt cap is hit.
