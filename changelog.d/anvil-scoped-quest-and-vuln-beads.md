category: Fixed
- **Quest-failure beads are scoped to their anvil** - questgiver matched an existing bead on the title prefix `E2E failure: <quest>` across the whole beads database, so two anvils sharing one pool (Munin and Explorer do, deliberately) with a quest of the same name silenced each other: the second anvil's failure produced no bead at all. Ownership is now recorded per anvil and quest in the Forge state database and the lookup is by bead id. As a side effect, quest `login` no longer matches quest `login-admin`'s bead.
- **Vulnerability beads are scoped to their anvil** - vulncheck decided a bead already existed by searching for the raw vulnerability id anywhere in the JSON of every open bead, so a CVE affecting two anvils in one pool was reported for only one of them. The same search also matched a longer id containing the shorter one (`GO-2026-1234` inside `GO-2026-12345`) and any bead that merely mentioned an id in prose. Ownership is now pinned by bead id, and the fallback compares the anvil and the vulnerability id as whole parsed values.
- **One reading of bd's output instead of four** - `BdReportsNoSuchBead`, `BdCreatedBeadID` and `DecodeOneBead` move to `internal/executil`, beside the single bd entry point. They are claims about bd's behaviour, not any caller's, and the first is load-bearing: a copy that stops agreeing with the others reads a timeout as "that bead is gone" and files the duplicate the record exists to prevent.
- **Removed depcheck's unreachable per-package dedup** - `DedupCheck`/`BuildDedupCache` searched the whole pool for a package name and had had no caller since the consolidated per-anvil bead replaced per-package beads. It carried the same cross-anvil defect in suppression form; deleting it removes the defect rather than scoping a code path nothing runs.
