category: Fixed
- **Self-deploy fires for merges nothing announced** - Deploy was triggered only by a Bellows `pr_merged` event, which an `ext-*` PR never emits, so a manually merged PR never deployed: six merges left the daemon seven commits and five days behind `origin/main` with no deploy and no warning. The daemon now also compares its own running build against the deploy branch's tip on a timer (`self_deploy.skew_check_interval`, default 15m, negative disables) and takes the same drain-and-rebuild path a merge event takes — never a bare restart. A skew that cannot be measured is logged and never deployed on, and the same branch tip is not re-deployed every tick (`self_deploy.skew_retry_interval`, default 2h). (Forge-6858)
- **Needs Attention when a merged fix is still not running** - A skew a deploy has already been attempted and finished for — never one whose deploy is still draining — is escalated as a `version_skew` entry past `self_deploy.skew_attention_commits` (3) or `self_deploy.skew_attention_age` (24h), naming the running build, the tip and how long it has been behind. It is withdrawn as soon as the running build is current again, by a deploy or by a manual rebuild. (Forge-6858)
- **`self_deploy` settings hot-reload** - The whole block is re-read live (the skew check re-reads it each tick, a deploy reads it when triggered), but a config edit touching only `self_deploy` was not detected by the reload watcher, so it was reported as needing a daemon restart and then really did need one. (Forge-6858)
