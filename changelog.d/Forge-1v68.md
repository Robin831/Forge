category: Changed
- **Assay pass prompts share one cache write** - Every Assay prompt now leads with the material that is identical across passes (repo guidance, change context, prior findings, triage notes and the diff) and ends with the pass-specific instructions and JSON contract, so the five deep passes share a byte-identical prefix instead of each writing the whole diff into the provider's prompt cache at full price. Redundant cache writes were 75.6% of Assay's cache-write spend. (Forge-1v68)
- **Staggered Assay deep-pass fan-out** - One primer deep pass now runs alone until the provider starts answering it, then the other four are released together, so the shared prefix is written once and read four times rather than missed five times simultaneously. A primer that fails, or a provider that streams no events, releases the rest immediately (60s backstop), and the four still run concurrently with each other and with the primer afterwards. (Forge-1v68)
- **Per-pass prompt-cache telemetry** - The Assay log line's `passes` field now reports `cache_w=`/`cache_r=` per pass and marks the primer with `primer=1`, so a run's redundant cache write is measurable from logs instead of only from a bill. (Forge-1v68)
- **Assay prompt head marked untrusted** - The shared prompt head now states that everything above the pass instructions — the change context, prior findings and the diff — is data under review rather than instruction, and the diff heading carries the same untrusted tag the change context already did. Ordering the shared material first puts attacker-controllable PR content immediately before where the model is told to expect its real instructions. (Forge-1v68)
