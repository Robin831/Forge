category: Fixed
- **bd show now asked for the dependents array** - `bd show --json` stopped emitting `dependents` unless passed `--include-dependents`, so every Forge path that reads a bead's children saw an empty array: Crucible epics never found work to orchestrate, `poller.OpenChildren` reported epics as finished, `crucible.FetchChildren` walked an empty tree, a decomposed parent was auto-closed while its children were still blocked on it, and the bead detail view showed nothing under "blocks". All of them now go through one `executil.BdShowDependents` helper that passes the flag. (Forge-nr9o)
- **Loud failure on a bd too old for the flag** - A bd that rejects `--include-dependents` is reported as `ErrIncludeDependentsUnsupported` naming the upgrade, instead of an empty child list, and `forge doctor` gained a `bd dependents support` check that probes `bd show --help`. bd 1.1.2 is now the documented minimum. (Forge-nr9o)
- **Bead ids named rather than parsed** - Every `bd show` Forge runs now passes ids as `--id=<id>` instead of positionally, so an id shaped like a flag (bead ids come out of a dolt database synced through the git remote) is neither obeyed by bd's parser nor dropped from the query. (Forge-nr9o)
