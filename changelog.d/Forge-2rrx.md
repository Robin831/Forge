category: Added
- **Bellows detach honoured by the PR monitor** - A PR carrying `bellows_detached` is now muted end to end: Bellows emits no events for it — not the transitions, and not the "still failing CI" / "still conflicting" / "still unresolved threads" branches that re-fire on unchanged state — so no quench, burnish, rebase or Assay worker is dispatched for it. Its mergeability and terminal state are still refreshed every poll, so the PR panel keeps showing the truth about a PR nobody is watching. (Forge-2rrx)
- **Detached PRs read as "detached" on both front ends** - The `bellows-<anvil>-<n>` monitor row keeps its place rather than vanishing, but carries the new `detached` worker status instead of claiming Bellows is monitoring it. Hearth marks it `⊘`; Hearth 2.0 keeps it on the pipeline bar with a `muted` chip on the bead row and a `detached` caption under the PR stage. The label follows the flag in both directions on rows that already exist. (Forge-2rrx)
- **Standing problems re-detected on resume** - Re-attaching a PR clears its cached snapshot, so failing CI, merge conflicts and unresolved review threads that outlived the mute fire as fresh transitions instead of being swallowed as unchanged state. (Forge-2rrx)
