category: Fixed
- **Pipeline now treats Smith `error_during_execution` as a failure** - Smith results with a non-success result subtype (e.g. `error_during_execution` from a kill mid-tool) are now marked as failed even when ExitCode is 0. Previously these slipped through to Warden, which hard-rejected on the empty diff and surfaced a misleading "no diff" error instead of the real cause. (Forge-javh)
- **`RECHECK_PREVIOUS:` Smith escape hatch for environmental failures** - On review iterations, Smith may emit `RECHECK_PREVIOUS: <rationale>` to signal that the previous iteration's code is correct and the failure was environmental (and has been fixed or has resolved itself). The pipeline re-runs Temper against the iteration-1 commit; if it passes, Warden runs as normal, otherwise the bead is escalated to a human with both the rationale and the Temper failure attached. Capped at one use per bead — a second use is treated as a pathological loop and escalated. A new `smith_recheck` event records each use. (Forge-javh)
