category: Fixed
- **Smelter dedupes a warden-rule batch against itself before committing** - A batch is now clustered and consolidated across categories before it is measured against the rest of the rules file, so one check learned eight ways ships as one rule instead of eight copies in every Warden prompt. The old pass grouped by category first, and a learned rule's category is whichever the distillation session picked, so a cluster spread over `style`/`documentation`/`other` was invisible to it. (Forge-aszm)
- **Near-duplicate rules are detected by containment as well as Jaccard** - Jaccard cannot score a terse restatement of a verbose rule above `|short|/|long|`, which is why the shipped `dedup_threshold` of 0.6 clustered nothing at all across 727 real rules. A second criterion, `settings.warden.overlap_threshold` (default 0.55), measures how much of the shorter rule's vocabulary the longer one already contains; either criterion firing makes a pair a duplicate. (Forge-aszm)
- **Contradictory learned rules are surfaced instead of shipped silently** - Rules from one source PR that prescribe opposite orderings — a callback invoked under the lock versus after releasing it, persist-then-clear versus clear-then-persist — are reported in the batch PR's commit message and body, in the daemon log and by `forge warden consolidate`. They are never merged or dropped: which convention a codebase wants is a human decision. (Forge-aszm)
- **`warden.dedup_threshold` and `warden.archive_after_days` edits now hot-reload** - Both are resolved through a closure at flush time so an edit takes effect without a restart, but the config watcher did not detect either, so the closure kept reading the old value. (Forge-aszm)
- **Two learned rules sharing an ID are both kept** - A rule's ID is written by whichever distillation session produced it, so two comments on one PR routinely arrive named the same thing; the second was dropped from the pending queue by an ID check with nothing said about it — and it was exactly the restatement the new intra-batch pass exists to merge into the first. It is now stored under a suffixed ID, so both reach the file, cluster, and commit as one rule. Re-learning a rule already on file is still a no-op. (Forge-aszm)
- **Rule consolidation identifies cluster members by position, not by ID** - Where a rules file held two rules under one ID, merging a cluster removed both while archiving only the one the cluster contained — a rule of coverage deleted with no archive entry and nothing in the log. Both passes now remove exactly the rules they merged, and the intra-batch pass excludes a colliding ID and reports it rather than guessing which rule it was handed. (Forge-aszm)
- **Rule consolidation is switched off with a negative `dedup_threshold`** - The off switch was documented as `0`, which could never reach the daemon: `0` is the setting's zero value, so an unset config and an explicit `dedup_threshold: 0` both resolved to the default of 0.6 and consolidation could not be turned off at all. A negative value now disables both passes, matching how `archive_after_days` already reads its own disable. (Forge-aszm)
- **A batch merge never reclassifies a `security` rule out of review scope** - The intra-batch pass clusters across categories and gives the merged rule the cluster's dominant one, but a rule's category is a review-time gate: a `.cs` diff selects `security` and excludes `testing`. One `security` rule merged into two near-duplicate `testing` ones would silently stop being reviewed on the next .NET diff. Such a cluster is now split at the boundary instead, so both sides keep landing where they landed before. (Forge-aszm)
- **Contradictory rule pairs are announced once, not on every flush** - The scan runs over the whole rules file and a pair is only ever cleared by a human, so every flush re-emitted every pair ever found into the log and the activity feed. Each pair is now reported once per anvil; the batch PR still lists them all. (Forge-aszm)
- **Learned rule IDs are sanitized before reaching a published PR body** - A rule's ID is whatever the distillation model returned and nothing validates a character of it, so a backtick, a newline or an `@org/team` in one would have broken out of its code span, forged further sections or mass-notified a team in a PR body posted under Forge's own GitHub identity. IDs and source references now render through a closed alphabet. (Forge-aszm)
- **`warden.overlap_threshold` edits hot-reload too** - Added alongside the `dedup_threshold` and `archive_after_days` watcher entries, with tests: a setting missing from the watcher is inert in a way nothing errors or logs about. (Forge-aszm)
