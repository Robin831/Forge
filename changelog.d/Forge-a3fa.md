- **Preview links follow `preview_proxy_base` everywhere** - With host-based preview routing configured, `forge preview list` and the daemon's preview payloads now report `https://<label>.<base>/` instead of the loopback `host:port` the dashboard had already stopped showing. Every surface — the Preview button, the previews page and the CLI — builds its link with the same helper (`kiln.EntryURL`), so a URL read in the browser and one copied out of the terminal cannot diverge. Preview health checks and preview quest runs deliberately stay on the direct port. (Forge-a3fa)
