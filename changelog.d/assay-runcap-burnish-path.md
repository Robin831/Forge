- **The per-PR Assay run cap is enforced on the Burnish coordination path** - `assay.max_runs` exists so the Assay → Burnish → new-head loop terminates, and Bellows stops re-firing at the cap; `ensureAssayReviewedHead` is reached from the Burnish worker instead and checked enabled/shadow/head-SHA but never the cap, so it bypassed the termination condition entirely. Munin#5423 logged `run cap reached (2/2)` and then `(3/2)` from Bellows while Assay ran a third and fourth time from this path — each run blocking the fix it is meant to inform, since the call is synchronous, and each reviewing a diff the previous round's fix had just enlarged. The gate now mirrors `shouldEmitReviewNeeded`: `>=` rather than `==`, since the count can already exceed the cap when this path runs, and `max_runs <= 0` still means no cap.
