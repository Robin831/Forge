category: Fixed
- **Depcheck no longer needs a clean anvil working tree** - The dependency scan now fetches the checkout's upstream tracking branch and reads `go.mod`, `*.csproj` and `package.json` out of that ref's blobs instead of running `git pull --ff-only` first. A pull is refused whenever a tracked file has local modifications the incoming commits touch, so an anvil that must carry a permanent local edit (a pod-local `.beads/config.yaml`, bd's own additions to `.beads/.gitignore`) was skipped on that run and on every run after it. A fetch writes only to `.git`, so such an anvil is now scanned normally and its local modifications are intact afterwards. The staleness the pull guarded against is handled from the data instead: an update the tracking ref already pins at the latest version is no longer reported, so a merged-but-unpulled bump does not file a duplicate bead. (Forge-wfd2)
- **Depcheck reads the branch's real upstream** - The tracking ref comes from the checked-out branch's own `@{upstream}`, falling back to the same branch name on `origin`, rather than assuming `origin/main`. (Forge-wfd2)
- **Dependency reconciliation is scoped per project** - An update is only checked against the manifests that apply to the project it was reported for. Folding every `package.json` or `.csproj` in a repository into one map let a monorepo project that upstream had already upgraded silence the same, still-real update in its siblings. Central `Directory.Packages.props`/`Directory.Build.props` in ancestor directories still apply, as MSBuild itself applies them. (Forge-wfd2)
