category: Fixed
- **Depcheck no longer needs a clean anvil working tree** - The dependency scan now fetches the checkout's upstream tracking branch and reads `go.mod`, `*.csproj` and `package.json` out of that ref's blobs instead of running `git pull --ff-only` first. A pull is refused whenever a tracked file has local modifications the incoming commits touch, so an anvil that must carry a permanent local edit (a pod-local `.beads/config.yaml`, bd's own additions to `.beads/.gitignore`) was skipped on that run and on every run after it. A fetch writes only to `.git`, so such an anvil is now scanned normally and its local modifications are intact afterwards. The staleness the pull guarded against is handled from the data instead: an update the tracking ref already pins at the latest version is no longer reported, so a merged-but-unpulled bump does not file a duplicate bead. (Forge-wfd2)
- **Depcheck reads the branch's real upstream** - The tracking ref comes from the checked-out branch's own `@{upstream}`, falling back to the same branch name on `origin`, rather than assuming `origin/main`. (Forge-wfd2)
- **Dependency reconciliation is scoped per project** - An update is only checked against the manifests that apply to the project it was reported for. Folding every `package.json` or `.csproj` in a repository into one map let a monorepo project that upstream had already upgraded silence the same, still-real update in its siblings. Central `Directory.Packages.props`/`Directory.Build.props` in ancestor directories still apply, as MSBuild itself applies them. (Forge-wfd2)
- **NuGet version ranges are no longer read as pins** - A `PackageReference` pinned with NuGet's bracket syntax (`[1.2.3]`), an interval (`[1.0.0,2.0.0)`) or a float (`1.0.*`) was recorded verbatim, so a bracket-pinned patch bump was rewritten to `[1.2.3] → 1.2.4` and re-classified `major` (routing it to needs-attention instead of auto-dispatch), and an update upstream had already merged was never dropped. A bracket pin is now read as the exact version it is, and an interval or float pins nothing, so the package is passed through untouched. (Forge-wfd2)
- **A bare `<2.0.0` npm range no longer swallows a real major update** - Such a range excludes the version it names, but it normalized to that version and made the update read as already applied upstream. (Forge-wfd2)
- **A repo-root solution no longer reconciles repo-wide** - A `.sln`'s pin scope is the projects it references, read out of the solution file, rather than its own directory tree — which at the repository root is the whole repository, so a project the solution does not even reference could silence a real update inside it. Such a project is now scanned in its own right, and F#/VB projects are scanned as well as read. (Forge-wfd2)
- **Depcheck tells a missing manifest from a failed git** - Whether a path exists at the tracking ref is now decided by `git cat-file`'s exit code rather than by matching git's `fatal:` text, which is translated: on a non-English host every scheduled scan of a .NET- or Node-only anvil reported a Go manifest-read failure and wrote a `depcheck_failed` event, forever. (Forge-wfd2)
- **A project missing from the checkout is logged, not silently skipped** - The npm guard now stats the `package.json` rather than its directory (a manifest upstream added inside an existing directory made npm walk up and report the parent project's packages as this one's), and both ecosystems log each skip plus the case where no project was scannable at all — previously indistinguishable from "all dependencies up to date". (Forge-wfd2)
