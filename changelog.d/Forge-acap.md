category: Fixed
- **Green PRs no longer stall when the daily Assay budget is spent** - When today's Assay spend reached `daily_cost_limit_usd`, `shouldEmitReviewNeeded` stopped dispatching reviews — so any otherwise-green PR whose head advanced after its last Assay run (e.g. via Burnish) could never satisfy the `assay_up_to_date` ready-to-merge gate and silently stalled out of both the Ready-to-Merge and Needs-Attention panels until the UTC-midnight reset (observed: PR #4335, 7 PRs blocked at once). `assayUpToDate` now releases the gate when the daily cost cap is reached, mirroring the existing per-PR run-cap release (Forge-btpw); readiness is still gated by unresolved threads. (Forge-acap)
- **Assay config changes now hot-reload** - The config watcher's `applyChanges` did not diff the Assay block, so `reload()` early-returned on "no changes" and edits to `assay.*` (e.g. `daily_cost_limit_usd`) delivered via ConfigMap were silently ignored until a pod restart. `applyChanges` now detects global and per-anvil Assay config changes so they take effect live. (Forge-acap)
