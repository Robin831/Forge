category: Fixed
- **A remote that is not a repository is blocked, not transient** - git answers a broken `origin` with `does not appear to be a git repository` followed by `Could not read from remote repository`, and only the second line was in either pattern table — so the fault classified as an outage, escalated nothing, and retried quietly. An anvil whose origin had been repointed at a worker worktree that then vanished went a day unscanned that way, with bellows and PR reconcile failing every ten minutes beside it. The first line is now a blocked pattern, which puts the condition through depcheck's existing escalate-once path.
- **The blocked-scan message names the origin** - a new `CauseBadRemote` reads the checkout's `origin` and reports it, and says outright when it points inside the anvil's own directory: a repository is never its own upstream, a worker worktree under `.workers/` is deleted when its bead finishes, and Forge writes no remote URL anywhere — so the message sends the operator after the writer as well as naming the command.
- **Worker teardown checks the anvil's origin** - the same shared `.git/config` that `CleanStaleCoreWorktree` already guards, one key over. Checked when a worker worktree is removed because that is the last moment the bead that held it is known, which is what the incident had no way to establish afterwards.
