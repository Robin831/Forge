category: Fixed
- **Config hot-reload now catches Kubernetes ConfigMap updates** - The config watcher filtered fsnotify events by basename (`forge.yaml`), but a mounted ConfigMap update atomically swaps the `..data` symlink and never touches the file. So config changes delivered via ConfigMap — the production deployment path, where the config is mounted read-only — silently never hot-reloaded and required a pod restart to take effect. The watcher now also reacts to the `..data` rename, so per-anvil and global edits applied to the live ConfigMap (e.g. flipping an anvil's `auto_merge`) apply without a restart. (Forge-cmrl)
