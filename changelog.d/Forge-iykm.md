category: Fixed
- **Empty-branch runs no longer fail at PR creation** - When a pipeline is approved but its branch has no commits against the base (the work already landed on main, e.g. a sibling PR shipped it first), Forge now skips PR creation instead of failing with "No commits between main and forge/<bead>" and retrying futilely. The outcome emits a `smith_empty_result` event and is resolved by the new `settings.empty_diff_action` config key: `attention` (default) raises a Needs Attention entry, `close` closes the bead with a note. Neither mode schedules a retry or counts against the dispatch circuit breaker. (Forge-iykm)
