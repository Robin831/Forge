category: Changed
- **Warden rule staleness now bites: `archive_after_days` defaults to 90** - At the shipped 180 the Smelter's staleness sweep was inert on exactly the files it exists to bound — on an anvil whose rules file had reached four figures, the rules added in 2026-04, -05 and -06 were all younger than 180 days, so Pass 2 archived nothing while the file kept growing. A convention still being violated keeps producing review comments, which refresh a rule's source activity and hold it out of the sweep, so 90 days removes a rule nothing has raised in a quarter — and the archive keeps it, so lengthening the threshold is enough to want it back. (Forge-ce9d)
- **The active rules-file ceiling defaults to 300 instead of 1000** - 1000 is the four-figure size the ceiling exists to prevent, set as the ceiling. A review reads `max_rules_per_review` (30) of the file, and across their whole PR history only 61 of one anvil's 1793 rules and 125 of this repository's 727 could reach a review at all, so a ceiling in the low hundreds sits above what is reachable rather than cutting into it. The ceiling remains the unconditional backstop behind the three consolidation passes, evicting the lowest-value rules into the archive under reason `over-cap`; `max_rules_in_file: -1` still switches it off. (Forge-ce9d)
- **The consolidation summary reports how full the rules file is** - The flush summary line, the batch PR body and `forge warden consolidate` now carry the post-pass rule count against the ceiling it was held to (`288/300 on file`, `Active after: 288 (ceiling 300)`) whether or not anything was evicted: at "0 evicted" a file at half the ceiling and a file one rule under it read identically, and only the second is about to start losing a rule every flush. Omitted entirely when no ceiling is in effect. (Forge-ce9d)
