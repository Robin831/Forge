Notes:
  - The substance axis is head_sha and nothing else: assay_runs records no diff hash, no
    changed-file set, no diff size and no base SHA. 'unchanged' means the previous run of
    the same PR reviewed the same head commit — the same key Assay's own re-dispatch gate
    (LastReviewedSHA) uses.
  - 'changed' is a proxy, not a proof: a push touching only a generated file moves the head
    while leaving the reviewable diff identical. It errs towards NOT claiming recoverable
    spend, which is the safe direction for a build/don't-build decision.
  - The base branch a diff is taken against is not recorded, so two runs over one head SHA
    whose base moved between them are counted 'unchanged' here. That over-states the
    recoverable cell rather than under-stating it.
  - NO COVERAGE counts the 4 run(s) ($3.13) in this population that reported zero findings
    because no pass ever ran (a failed run), not because a review read the diff and found
    nothing. Their spend still counts — a failure is not a refund — but a skip heuristic
    could not recover it: there was no review to skip.
  - PREV CLEAN / PREV HAD FINDINGS split each repeat cell by what the PRECEDING run
    reported, since a skip heuristic would key on 'the last review of this head was clean'
    rather than on 'this is a repeat'.
  - Ordinals and predecessors are derived over each PR's full review history, then
    restricted to the window (cost.DeriveRunOrdinals — the same definition forge cost assay
    uses).
